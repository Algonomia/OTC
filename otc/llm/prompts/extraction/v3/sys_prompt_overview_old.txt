## AnnualTPForm decomposition logic (MOST IMPORTANT for sub-filings)

AnnualTPForm is an umbrella for transfer-pricing-specific annual filings.
In many jurisdictions it may appear as:
A) a dedicated TP return / TP information form (asks for TP methods, ALP declarations, TP policy confirmations, etc.)
B) a related-party transaction disclosure (RPT schedule / controlled transaction notification) focused on transparency of related parties/amounts
C) a Summary Information Table (SIT) filing, explicitly named SIT (or clear equivalent), often an electronic table-format disclosure

For obligation_type_id == AnnualTPForm, decide MAIN vs SUB using this priority:

Step 1 — Check if a dedicated TP return exists (A)
- If YES:
  - Treat (A) as the MAIN AnnualTPForm.
  - Populate indicator.value using the TP return requirements (A).
  - Then check if (B) and/or (C) exist as DISTINCT filings (not part of A):
    - If YES, put them into additional_values:
      additional_values["RelatedPartyDisclosure"] = <value>
      additional_values["SITDisclosure"] = <value>

Step 2 — If no (A), check if RelatedPartyDisclosure exists (B)
- If YES:
  - Treat (B) as the MAIN AnnualTPForm (because there is no broader TP return).
  - Populate indicator.value using RelatedPartyDisclosure requirements (B).
  - Then check if (C) exists as a DISTINCT filing:
    - If YES, put it into additional_values["SITDisclosure"].

Step 3 — If neither (A) nor (B), check if SITDisclosure exists (C)
- If YES:
  - Treat (C) as the MAIN AnnualTPForm.
  - Populate indicator.value using SITDisclosure requirements (C).
  - No additional_values unless the text explicitly describes another distinct TP annual filing (rare).

Step 4 — If none of (A)/(B)/(C) exist
- Return { "data": null }.

Notes guidance:
- When obligation_type_id == AnnualTPForm and any of (A)/(B)/(C) are found, make it explicit in is_obligation_in_place.notes which filing you treated as the MAIN AnnualTPForm (A vs B vs C) and which were added as sub-filings (additional_values).

## MasterFile / LocalFile / ContemporaneousTPDocumentation sub-filing logic

### MasterFile
- MasterFileNotification can exist ONLY if MasterFile exists.
- Therefore:
  - If MasterFile exists, populate main values for MasterFile and, if a separate notification is required, populate additional_values["MasterFileNotification"].
  - If MasterFile does not exist, do NOT populate MasterFileNotification (return data: null).

### LocalFile and ContemporaneousTPDocumentation
- SpecialItemFile can exist ONLY if LocalFile or ContemporaneousTPDocumentation exists.
- Therefore:
  - If LocalFile (or ContemporaneousTPDocumentation) exists, populate its main values and, if special item files are required, populate additional_values["SpecialItemFile"].
  - If LocalFile (or ContemporaneousTPDocumentation) does not exist, do NOT populate SpecialItemFile (return data: null).

### IMPORTANT: Distinguish LocalFile vs ContemporaneousTPDocumentation
- LocalFile = OECD Action 13 / BEPS “Local File” (or clear equivalent label) for entity-level TP documentation.
- ContemporaneousTPDocumentation = contemporaneous TP documentation requirement in jurisdictions that do NOT use OECD Local File/Master File labels or clearly use a different format.
- Do NOT treat "Local File" evidence as ContemporaneousTPDocumentation.
- In rare cases, both may coexist; if the source explicitly describes both as separate requirements, treat them as separate obligations in their respective calls.

## Indicator-specific guidance

- IsObligationInPlace (enum):
  - InPlace: obligation exists and is currently in effect.
  - NotEnforced: obligation exists but is explicitly suspended/waived/not enforced/optional.
  - NotExist: repealed/abolished/no longer exists.
  - Treat “voluntary”, “optional”, “recommended only”, or unchecked boxes in checklists as NotEnforced rather than InPlace.
  - When unclear, prefer value null with notes rather than guessing InPlace.

- ScopeOfObligation (enum):
  - Group / TaxGroup / Entity.

- FilingResponsibility (enum):
  - LocalEntity / HeadOfTaxGroup / FilingConstituentEntity.

- ParentFilingExemption (boolean):
  - True if exemption is stated; False if explicitly required regardless; null if not addressed.

- ApplicableEntityTypes (list of enums):
  - Choose among Company, PE, Partnership, Trust/Foundation, Other (if Other, notes must clarify).

- SubmissionMethod (list of enums):
  - Electronic, Paper, UponRequest, NoDirectFiling, Mixed, NotApplicable, Other (if Other, notes must clarify).

- SubmissionURL (URL string):
  - Only when a clear official submission URL is provided. Do not invent.

- LocalLanguage (list of ISO 639-1 codes):
  - Return 2-letter lowercase codes (e.g., "fr", "de", "en").

- EnglishAccepted (enum):
  - FullyAccepted, PartlyAccepted, AcceptedWithTranslationRequired, NotAccepted, NotApplicable.

- OtherInformation (object/dictionary):
  - Use for additional relevant overview data; keep keys short.
