*Tags*

-Custom tags: if the suitable tag is not listed in ThresholdPenaltyTagName, define a custom tag with is_custom=True (by default is_custom=False when the tag is from the predefined enum list).

*Operators (IDs)*   
-Boolean: and, or, not.
-Comparators: >, >=, <, <=, == (2 args; compatible types).
-Arithmetic (numeric): *, +, -, /, %.
-Aggregators (numeric): min, max.
-Branching:
--Use custom tags (is_custom=true) to represent penalty triggers (e.g., "late_submission", "has_errors") when no other suitable tags exist in ThresholdPenaltyTagName.
--if(cond:boolean, then:*, else:*) – takes always 3 arguments; then/else must share the same type class; if no default value after else:, return null for the third argument.
--case(trigger_1,value_1,trigger_2,value_2, …, default) – can be used for either mutually-exclusive triggers or for providing different outcomes based on the trigger input; all val* + default share the same type class; if no default value needed, return null or null constant range for the last argument.
-Dates: date_add, date_sub, date_diff, date_min, date_max, next_md_after, bom, eom.
-Intervals: prefer boolean intervals and(>=(x,lo), <=(x,hi)). Reserve between(lo,hi) for literal intervals.
-Ranges (for penalties): to_range(x) (scalar → [x,x]), range(a,b) (dynamic bounds).

*Case construction (STRICT)*
- ARG POSITION RULE: In case.args, every ODD position (1st, 3rd, 5th, ...) MUST be a TAG node whose tag.expected_type = "boolean".
- Those boolean trigger tags MUST be custom (is_custom=true) unless an identical predefined tag already exists (rare for triggers).

- Even if a trigger would be trivially true, still express it as a boolean custom tag (concise, snake_case, readable for tax specialists with limited IT experience).
- The EVEN positions following each trigger are the value expressions (they must yield a range).
- If you need sub-logic (e.g., >= 112 days for late submission), put it inside the value expression (if / arithmetic) OR define a second boolean tag (threshold_penalty.late_submission_of_112_days_or_more) as a separate trigger with its own value expression.
- Final default (if provided) MUST be a range expression; if no default, append a null constant range: use to_range(0) or omit the default entirely (then last arg count is 2 * triggers).

*Penalty construction (value = case based IComplexValue)*

-penalty.value must use a root case that specify different triggers and the potential penalty calculation logic for each trigger:

--Each value is an IComplexValue expression for that trigger.
---Each trigger's expression should ultimately yield a range:
----either by using operation.to_range(<numeric_expr>),
----operation.range(<min_expr>, <max_expr>), or
----an IRangeConstant.
---Apply any caps/floors using min/max inside each trigger's expression before normalization.
-If a penalty category does not apply or is unspecified, omit the key (don’t fabricate).
